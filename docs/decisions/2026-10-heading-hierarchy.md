# 2026-10: 제목은 답으로, 구성안은 산출물 언어로, 위치 표시는 본문 열 안에

## 상태

확정 (2026-10-29). HTML 스킬 네 개(eli5, visual-doc, explain-diff, micro-world)와 텍스트 스킬 여섯 개에
적용. 배경이 된 산출물은 2026-10-28의 eli5 "업무용 AI 에이전트의 정량 평가" 페이지와 그 구성안이다.

## 배경

- 비유와 번역투 금지, 이식 검사(다른 주제에 옮겨도 말이 되는 제목은 탈락)가 이미 네 SKILL.md에 있었는데도
  구성안 단계에서 `시험을 어떻게 내는가`, `점수 읽는 법`, `우리가 직접 재려면`, `한 번 맞추기 vs 열 번 연속
  맞추기`, 주제 전체를 `모의고사`로 감싸는 틀이 그대로 나왔다. 사용자는 `~한 축`, `4축`, `왜 아닌가` 같은
  표현을 AI 문체의 표지로 지목했다.
- 새는 지점은 셋이었다. (1) 규칙이 전부 HTML 파일을 대상으로 쓰여 있어 채팅에 내놓는 구성안은 검사를
  받지 않았고, 구성안의 제목이 그대로 h2가 됐다. (2) 금지 목록이 비유와 번역투 예시뿐이라 질문형, `N축`,
  `~하는 법`, 단독 `A vs B`, `핵심은`/`결국` 같은 구조적 틀은 열거되지 않았다. (3) 기본 arc의 역할 이름이
  영어(`The trap: why the obvious fix breaks`)라 모델이 영어로 역할을 세운 뒤 한글로 옮겼고, 그 번역
  단계에서 `왜 ~는 안 되는가`가 생겼다.
- 같은 페이지에서 두 번째 피드백: 내용이 길어질수록 단락 구분이 없어 지금 어디를 읽는지, 이 내용이 하위
  항목인지 알 수 없다. 제목에 번호가 늘 붙는 것도 아니었다(테이블 해설 문서는 앞 두 섹션은 번호 없음, 뒤
  10개만 번호). 사이드 리모컨(TOC rail)은 좌우 밸런스를 깨서 원하지 않는다고 했다.

## 결정

### 제목

- **제목은 답이지 틀이 아니다.** 제목, 소제목, 캡션, 차례 줄, 구성안에서 다음 패턴을 쓰지 않고 가리고
  있던 사실을 쓴다. 질문형(`~하는가`, `~인가`, `~일까`, `왜 ~인가`)은 답으로. 분류 틀 명사(`N축`, `~한 축`,
  `차원`, `관점`, `레이어`, `측면`)는 축의 이름으로. 방법 명사화(`~하는 법`, `~읽는 법`, `~하려면`)는 대상과
  값으로. 단독 `A vs B`는 갈리는 값으로. 강조 틀(`핵심은`, `결국`, `본질적으로`, `진짜`, `단순히 ~가 아니다`,
  `~에 불과`)은 삭제. 개수를 먼저 정하고 채워 넣지 않는다. 주제 전체를 감싸는 비유(`모의고사`, `장부`)는
  제목과 구성안에 쓰지 않는다 (`.say` 한 줄의 기존 예외는 유지).
- **본문은 대상이 아니다.** `A vs B`나 `~하려면`은 본문에서 평범한 문장이다. 전역 grep으로 금지하지
  않는다. Render check에 제목 태그(`h1`~`h3`, `.dg-cap`)만 보는 grep을 5번으로 넣되, 결과는 소리 내어
  읽고 판단할 목록이고 실패가 아니다. 남긴 제목은 보고서에 이유와 함께 적는다.
- **구성안은 처음부터 산출물 언어로, 최종 제목 그대로.** 채팅에 보여주는 구성안도 같은 기준을 통과해야
  한다. 이를 위해 산출물 문장을 정하는 절(eli5의 Step 2 storyboard와 "제목은 그림이 무엇인지 말한다",
  visual-doc "구성안은 산출물 언어로", explain-diff "Section titles" 첫 문단, micro-world 제목 줄)은
  SKILL.md 안에서 한글로 쓴다. arc의 역할 이름에는 한글 예시 제목을 하나씩 붙였다(`그 해법이 깨지는 조건.
  예: 쿼리 글자 하나만 달라도 캐시 미스, 적중률 3%`). AGENTS.md "언어" 절에 이 예외를 적었다.
- 텍스트 스킬 여섯 개의 `Writing rules`에는 같은 내용의 축약(`Titles are answers, not frames`)을 넣었다.
  PR 제목 `왜 X를 걷어냈는가`가 같은 병이다.

### 위치 표시

- 네 템플릿에 같은 코드의 `section hierarchy (SHARED` CSS 블록과 body 끝의 같은 이름 스크립트를 넣었다.
  상단 3px `.progress` 진행바(스크롤 비율로 채워지고 글자는 없음), 머리 바로 아래 한 번만 나오는 `.outline`
  차례, 상위 섹션의 가로선(`.sec-top`)과 번호 줄(`.sec-no`, `01 / 07`), 하위 섹션의 왼쪽 막대(`.sub-h`)와
  번호(`.sub-no`, `01.1`). 번호는 이 줄에만 있고 제목 글자에는 넣지 않아 제목은 명사구로 남는다.
- **두지 않는 것.** 사이드 TOC rail(visual-doc의 `.toc-rail`을 제거)과 섹션 이름이 붙은 고정 머리. 시안
  단계에서 38px 고정 머리에 현재 섹션 제목을 띄워 봤으나 사용자가 부적절하다고 판단했고, 진행바만
  남겼다.
- **템플릿마다 쓰임이 다르다.** eli5는 beat마다 번호 줄과 차례(하위 없음). visual-doc은 챕터(`.group-label`)가
  상위, 카드가 하위이고 `.list-header .num` 배지는 제거했다. explain-diff는 Part가 상위(`01 / 03`), 섹션
  카드가 하위(`.sub-no`는 카드 번호이고 TOC의 `.idx`와 같은 수)이며 기존 TOC 카드가 차례 역할을 하므로
  `.outline`은 쓰지 않는다. micro-world는 한 화면이라 진행바만 넣고, 상위 섹션이 4개 이상일 때만 번호 줄과
  차례를 쓴다. 제목 글자 크기(`.g-name`, `.sub-h h2`, `.sub-h h3`)는 공유 블록 밖에서 템플릿마다 정한다.
- 시안은 2026-10-28 eli5 벤치마크 페이지와 2026-08-03 테이블 해설 문서에 적용해 Before/After로 확인했다.
  테이블 해설 문서에서는 "테이블별 상세" 아래 10개 그룹이 하위라는 것이 처음으로 보였다.

## 검토한 대안

- 제목 패턴을 전역 grep으로 금지: 본문의 `vs`, `~하려면`이 멀쩡한 문장이라 사용자가 거부했다. 제목 태그
  한정, 읽을 목록으로 완화했다.
- SKILL.md 전체를 한글로: 번역 문제는 산출물 문장이 태어나는 절에만 있다. CSS, 측정, 접근성 절은 코드라
  영어로 둔다.
- 고정 머리에 현재 섹션 제목 표시: 좌우 폭에는 영향이 없지만 위 38px를 쓰고, 번호 줄과 차례로 충분하다고
  판단했다.
- 번호를 제목 글자에 넣기(`01. 벤치마크 구성`): 제목이 명사구에서 멀어지고, 차례와 TOC에서 번호가 두 번
  찍힌다. 번호는 별도 줄에 둔다.
