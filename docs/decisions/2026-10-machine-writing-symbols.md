# 2026-10: 기계 문장 기호 금지를 모든 스킬로

## 상태

확정 (2026-10-23). em-dash(`—`), en-dash(`–`), 가운뎃점(`·`)을 git-claw의 모든 스킬 산출물에서
쓰지 않는다. 스킬 지시문, 템플릿, README, AGENTS.md에서도 걷어낸다.

## 배경

- dash 금지는 git 메시지(커밋, PR)와 HTML 문서 스킬 네 개에만 있었다. issue, review-reply,
  code-review, handoff에는 규칙이 없었고, 가운뎃점은 어느 스킬에서도 금지하지 않았다.
- 스킬 파일 자체가 금지 문자를 많이 썼다. 정리 전 기준으로 SKILL.md와 템플릿에 em-dash가
  약 400곳, 가운뎃점이 약 130곳 있었다. 모델은 지시문의 문체를 따라 쓰므로, 지시문이 쓰는 기호는
  산출물로 새어 나온다.
- 출력 템플릿에 금지 문자가 직접 들어 있던 곳도 있었다. 모든 스킬이 쓰는 Hint 형식
  (`> **⚡ Amend** — ...`), code-review의 Codex 출처 태그(`— Codex`), 상태 줄의 구분자
  (`🔴 n critical · 🟡 ...`)는 결과물에 그대로 찍혔다.
- 사용자 피드백: em-dash와 가운뎃점은 AI가 쓴 글의 대표적인 표지이고, 산출물은 자연스러운
  한국어여야 한다.

## 결정

- **금지 범위.** 모든 스킬이 만드는 글(커밋, PR, 이슈의 제목과 본문, 리뷰 코멘트와 답글, handoff,
  터미널 Hint, HTML 문서의 모든 글자)에 em-dash, en-dash, 가운뎃점을 쓰지 않는다.
- **바꾸는 법.** dash는 콜론, 괄호, 쉼표, 문장 나누기로 바꾼다. 항목 사이 가운뎃점은 쉼표나
  `와`/`과`로, 라벨 안의 구분용 가운뎃점은 쉼표나 줄바꿈으로 바꾼다. 범위는 `~`로 쓴다.
- **예외는 원문 인용 하나.** 코드 블록, diff 블록, 근거 카드, 인용으로 표시한 리뷰어 코멘트 안의
  원문은 글자를 바꾸지 않는다. 산문 속 인용은 금지 문자가 없는 짧은 구간만 인용하고, 인용을 고쳐
  쓰지 않는다. visual-doc 예시 생성에서 "원문 그대로 인용"과 "dash 금지"가 충돌한다는 지적이 나와
  이 순서를 명시했다.
- **규칙의 위치.** 텍스트 스킬 여섯 개(commit, pr, issue, review-reply, code-review, handoff)에는
  `Writing rules (shared across commit` 소절을, HTML 스킬 네 개에는 `No machine-writing symbols`
  항목을 같은 글로 넣었다. 자연스러운 한국어 규칙(조사 붙여 쓰기, 군더더기 명사 빼기, 비유와
  번역투 금지, 횟수는 숫자로)과 보내기 전 확인(`grep -nP '[—–·]'`)이 함께 들어 있다.
- **출력 형식 변경.** Hint는 `> **{icon} {action}**: {reason}`. code-review의 Codex 출처 태그는
  `(Codex)`, `(Codex Adv)`. 판정 줄은 `> **Recommendation**: Accept, {이유}`처럼 콜론을 한 번만
  쓴다 (dash를 기계적으로 콜론으로 바꾸면 `Accept: 이유`처럼 콜론이 연달아 찍혀서 고쳤다).
  commit 계획 표시는 `{subject} (N files) [category]`.
- **스킬 파일 정리.** 지시문의 단독 ` — `는 콜론, 한 줄의 짝 dash는 괄호로 바꾸고, 콜론이
  연달아 찍히는 63곳과 짝이 어긋난 곳은 손으로 고쳤다. 한글 `A·B`는 받침에 맞춰 `A와 B`/`A과 B`로,
  셋 이상은 쉼표로 바꾼 뒤 어색해진 곳(`상·하한` → `상한과 하한`, `원문·유령 줄·ERD` → 쉼표 나열)을
  손으로 고쳤다. 레이아웃 계획 주석의 구분자는 ` | `로 바꿨다. 금지 규칙 문장과 grep 패턴 안의
  기호만 남는다.

## 검토한 대안

- 지시문(영어)은 두고 출력 템플릿만 정리: 지시문 문체가 산출물로 새는 경로가 남는다.
- 가운뎃점 허용(국립국어원 문장 부호 규정은 열거에 가운뎃점을 허용한다): 규정상 맞지만 사용자가
  AI 문체의 표지로 판단했고, 쉼표나 `와`/`과`로 바꿔도 뜻이 같다.
- CHANGELOG와 결정 문서의 지난 기록까지 정리: 당시 작성본이라 고치지 않는다. 새로 쓰는 항목만
  규칙을 따른다.
