# 2026-11: AGENTS.md는 작업별 문서 표만, 절차와 상세는 docs로

## 상태

확정 (2026-11-11). `AGENTS.md`에는 어느 작업에나 적용되는 규칙과 작업별 문서 표만 두고,
특정 작업에서만 필요한 절차와 상세는 `docs/` 아래 문서로 옮긴다.
그림으로 정리한 계획 문서: docs/decisions/2026-11-doc-routing.html

## 배경

- **Codex가 `AGENTS.md`의 뒤쪽을 읽지 못했다.** Codex는 프로젝트 지침 파일을
  `project_doc_max_bytes`(기본 32KiB)까지만 읽고 넘는 부분은 잘라낸다
  (openai/codex `codex-rs/core/src/agents_md.rs`). `AGENTS.md`는 59,051바이트였고 이 환경의
  Codex 설정에는 그 항목이 없어서, 스킬 공통 규칙 중간부터 터미널 렌더링, 스킬 간 공유 로직,
  체크리스트, 릴리스 절차가 전달되지 않았다. 파일 크기와 소스로 계산한 위치이고 Codex를 실행해
  경고를 확인한 것은 아니다.
- **파일이 계속 커졌다.** 2026-07-18 27,168바이트, 09-30 33,275바이트(이때 상한을 넘음),
  10-23 45,672바이트, 11-10 58,940바이트. 로컬 테스트(16.8KB)와 스킬 간 공유 로직(16.4KB)
  두 구역이 절반을 넘었다.
- **같은 글이 세 곳에 있었다.** 공유 로직 표의 행이 "같이 고칠 곳"을 넘어 개정 날짜와 바뀐 값까지
  담았고, 같은 개정이 결정 문서와 CHANGELOG에도 적혀 있었다.
- **Claude Code에서도 길었다.** 공식 권장은 파일당 200줄 이하인데 529줄이었고, `@` import는
  세션 시작 때 전부 로드되므로 크기를 줄이는 수단이 아니다.

## 결정

1. `AGENTS.md`에 남기는 것: 문서 체계, 개요, 아키텍처, 배포, 작업별 문서 표, Git Convention의
   규칙, 언어. Git Convention의 규칙은 `/commit`, `/pr` 스킬이 프로젝트 설정을 `AGENTS.md`에서
   찾으므로 옮기지 않는다.
2. 작업별 문서 표는 "이 작업을 할 때, 먼저 읽을 문서" 두 칸이다. 에이전트가 자기 작업과 바로
   대조할 수 있는 말로 왼쪽 칸을 쓴다.
3. 옮긴 문서: `docs/testing.md`, `docs/skill-rules.md`(공통 규칙과 체크리스트 2개),
   `docs/shared-logic.md`, `docs/terminal-rendering.md`, `docs/release.md`,
   `docs/ops/plugin-sync.md`, `docs/ops/skills-cli.md`. 글은 고치지 않고 옮겼다
   (제목 단계와 서로를 가리키는 문장만 맞췄다).
4. 공유 로직 표는 번호, 이름, 관련 스킬, 찾을 표식, 정본 다섯 칸으로 줄이고, 원래 비고 칸의 글은
   같은 파일의 "상세" 절에 번호를 맞춰 그대로 둔다.
5. `AGENTS.md`는 32,768바이트 이하로 유지하고, 확인 명령을 문서 체계 절에 적는다.
6. `docs/` 문서는 `@` import로 연결하지 않고 경로만 적는다.

## 검토한 대안

- **`project_doc_max_bytes`를 올린다**: 내 환경만 고친다. 이 저장소를 받는 다른 Codex 사용자에게는
  효과가 없다. 기각
- **`.claude/rules/`의 `paths:` 규칙**: 해당 파일을 건드릴 때만 로드되지만 Codex는 읽지 않는다.
  정본을 에이전트 중립 파일에 두는 2026-07 결정과 어긋난다. 기각
- **항상 지킬 규칙을 모두 `AGENTS.md`에 남긴다**: 스킬 공통 규칙과 터미널 렌더링은 스킬을 고칠 때만
  필요하고, 그 시점은 작업별 문서 표로 특정할 수 있다. 남기지 않는다

## 영향

- 에이전트가 표를 보고도 문서를 열지 않을 수 있다. 표의 왼쪽 칸이 흐리면 생기는 문제이므로,
  새 문서를 추가할 때는 "언제 읽는지"를 먼저 정한다.
- 스킬 변경 체크리스트의 갱신 대상이 `AGENTS.md`에서 `docs/skill-rules.md`, `docs/testing.md`,
  `docs/shared-logic.md`로 바뀐다.
- 후속: 결정 문서 목록(`docs/decisions/README.md`)과 eli5 결정 문서의 이력 분리, 이름이 내용과
  어긋난 결정 문서 2개의 개명, CHANGELOG의 옛 항목 분리.
