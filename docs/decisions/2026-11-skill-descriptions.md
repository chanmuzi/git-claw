# 2026-11: 스킬 description은 고르는 기준만

## 상태

확정 (2026-11-11). `2026-08-eli5.md` 원본 결정 3번의 "네 스킬의 `DO NOT TRIGGER` 절이 서로를 가리킨다"를 대체한다.
독자로 가른다는 결정 자체는 그대로다.

## 문제

스킬 10개의 description이 330~832자였다. 한 문장의 설명 뒤에 `TRIGGER when`과 `DO NOT TRIGGER when` 목록이 붙고,
목록의 대부분은 요청 문구 예시(`"커밋해줘"`, `"리뷰 돌려줘"`)였다.

- description은 스킬을 고르는 단계에서 모든 세션에 실리는 글이다. 길수록 그 단계에서 읽을 것이 늘어난다.
- 사용자는 대개 스킬을 이름으로 부르거나 작업 규칙에 적어 둔다. 요청 문구 예시가 고르는 데 쓰이는 경우가 드물다.
- 문구 예시는 나열에 없는 문구를 설명하지 못한다. 고르는 기준은 "무엇을, 어떤 상황에, 누구를 위해"이면 충분하다.
- 실행 지침은 스킬이 로드된 뒤 본문에서 읽는다. description에 둘 이유가 없다.

## 결정

- description은 무엇을 만드는지와 어떤 상황에 누구를 위해 쓰는지를 한두 문장(250자 안)으로 쓴다.
- `TRIGGER when`, `DO NOT TRIGGER when` 목록과 요청 문구 예시를 없앤다.
- 문서 스킬 네 개(`explain-diff`, `micro-world`, `visual-doc`, `eli5`)는 `The reader`로 시작하는 문장 하나로 독자를 말한다.
  넷을 가르는 기준은 이 문장이고, 서로를 가리키는 절은 두지 않는다.
- 헷갈리는 짝이 있는 스킬만 상대를 가리키는 한 문장을 둔다: `code-review`와 `review-reply`, `explain-diff`와 `code-review`.

## 확인하지 못한 것

Claude Code 밖의 agent(Codex CLI 등)에서 이름 없이 요청했을 때 스킬이 전과 같이 골라지는지는 재지 않았다. 잘못 고르는 사례가
나오면 문구 예시를 되살리지 않고 "어떤 상황에" 문장을 고친다.
